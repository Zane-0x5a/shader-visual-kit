# Paper Shaders 项目接入

先定位宿主的依赖版本、入口、资源路径和实际输出目标。视觉源码、原生参数、预设、图片及运行依赖由宿主项目持有；本 Skill 是开发期知识与可复制辅助代码，不是产品运行时。无需 Paper Desktop。

## 从描述到效果

用户用文字描述画面时，一个词常有几种看上去截然不同的**读法**。例如“光影”既可以是从一处射入的光束（GodRays），也可以是铺满画面、缓慢流动的多色形体（Warp、MeshGradient）。

- 按描述里的可见特征拆出读法：铺满画面还是局部，流动还是静止，单色还是多色，光线还是形体。效果名只是索引；名字与用词对上，不代表画面对上。
- 用户给了参考图、点名了效果，或描述只有一种合理读法时，直接按它做。有几种读法时，先用一句话列出各读法，在宿主真实入口里每种读法渲染一张候选，用户选定后再展开。
- 候选围绕当前任务和宿主准备，是任务中的预览，不是常驻 landing page；工具自带的固定示例只用于演示和测试，不能替代真实项目的候选与反馈流程。
- 效果只落在用户指定的那一层。再加一个着色器，或把同一效果的光与色延伸到边框、按钮等控件上，都是新的视觉选择，同样先作候选。

## 选择原生入口

- 已有项目沿其构建、主题与目录约定接入。React 可直接使用 `@paper-design/shaders-react`，其他浏览器宿主按自身生命周期使用 `@paper-design/shaders` 的 `ShaderMount`。SSR 在客户端挂载 WebGL，卸载时 dispose。
- 官方效果、参数、预设可直接使用。先从 https://shaders.paper.design/llms.txt 找官方入口，再用项目已安装的类型和源码确认接口；不在工具中登记效果白名单或复制参数协议。
- 尚无项目时，在本次任务的产物目录建立适合目标的普通项目，保留源码、资源和 lockfile。首次安装选择当时适用版本；已有项目保持其版本，升级作为显式项目改动。
- 作整页背景时，着色器层须位于全部常规内容之下（如 `position: fixed; z-index: -1`，并让会盖住负层级的 body 背景让位）；`z-index: 0` 的不透明层会遮住页面主体容器之外未定位的元素。验证须覆盖 SSR 或静态导出的首屏、登录与数据加载态等主体容器之外的状态。
- speed 不为 0 时，ShaderMount 用 requestAnimationFrame 按显示器刷新率持续重绘，只在页面隐藏或移出视口时停。慢速流动的常驻背景可把 speed 设为 0，由宿主时钟推进 `frame`，按可见性逐级降帧、隐藏时停止，并设 `maxPixelCount`。实际省下多少，按下文的方法在宿主里测。
- 把效果套在非方形元素上（如用 PulsingBorder 作面板边框）时，核对官方组件默认的 scale、fit 与 aspectRatio，默认值可能把图形缩成居中的方块。
- 多个色相以低透明度叠在浅底上，或 MeshGradient 远离各色点处（显示色板的加权平均），互补色会混成灰褐，容易被读成污渍。优先用不透明色场，并用底色色点把平均色拉回底色。
- 需要 Remotion 确定性取帧、纹理就绪或视频导出时，先读 [Remotion 接入](references/remotion.md)。

## 验证与展示

沿宿主真实入口验证效果。检查实际像素、尺寸、纹理和生命周期；对涉及的视频输出执行真实导出。HTTP 成功和类型检查只证明各自环节，不代表视觉正确。常驻效果在真实窗口尺寸下用系统计数器测 GPU 与 CPU，并在窗口隐藏、最小化后再测一次：嵌入式 WebView 的宿主隐藏窗口时，页面未必收到隐藏通知，以实测停帧为准。

比较性能要控制变量，否则数字不能归因：测试前确认机器的占用情况和基线是否干净；一次只改一个参数；数实际帧率，不按设定值推算；每种配置重复取样，记录窗口尺寸、焦点等测试条件；计数要对应目标进程及其实际使用的 GPU。

人工预览按需启用，必要渲染验证由 Agent 自行完成，无需额外人工审批。用户要看时使用当前代理宿主可用的浏览器能力；Codex 中优先内置浏览器，Claude Code 中使用已配置的浏览器工具，或提供可打开的本地 URL。已有服务直接打开其明确 URL；需要启动新服务时读 [预览进程](references/preview.md)。

交付说明项目中的效果入口、如何复用或调节，以及实际验证和未解决的问题。通用前端设计、素材创作与用户的视觉选择仍按原任务处理。
